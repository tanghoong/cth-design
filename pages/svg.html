08 — SVG & data graphics

SVG & data graphics

Icons, diagrams and the self-contained data cards on github.com/tanghoong. An SVG is a surface like any other — same tokens, same radius, same easing.

Where this came from The eight cards in the GitHub profile README are generated daily by scripts/generate-cards.mjs and committed as static SVG — no third-party badge service in the render path. They already use this system's tokens exactly: rx="20" is --r-lg, the card stroke is --hairline, the gridlines are --hairline-soft, and the animation is cubic-bezier(.22,1,.36,1) at 260/420 ms. This page writes that down so the next graphic matches without anyone having to reverse-engineer it.

Icons

Stroke icons on a 24 px grid, rendered at 16–20 px. Always currentColor — an icon that hard-codes a hex breaks the moment it lands on a filled button or in the other theme.

The icon contract

The same six on a filled accent — they inherit --accent-ink with no extra rule:

<svg width="20" height="20" viewBox="0 0 24 24"
     fill="none" stroke="currentColor" stroke-width="1.8"
     stroke-linecap="round" stroke-linejoin="round"
     aria-hidden="true">
  <path d="M5 12h14m-6-7 7 7-7 7"/>
</svg>

Decorative icons are aria-hidden="true" and the control beside them carries the aria-label. An icon that is the content gets role="img" and a <title> instead.

Chart colour

Six steps out from the accent. Light runs dark → pale, dark runs bright → deep. Assign --c-1 to the largest series and work down, so the ordering carries meaning rather than being arbitrary.

Six is the ceiling Past six categories nobody can match a colour back to a legend. Group the tail into "Other" and label it. If the data genuinely has twelve categories, a chart is the wrong form for it — use a table.

Stacked bar

The language-share idiom from the profile cards. One rounded track, segments in ramp order, a legend beneath with the figure as tabular numerals.

Stacked bar with legend
  • TypeScript 42%
  • Go 24%
  • Python 16%
  • CSS 9%
  • Shell 5%
  • Other 4%

The whole graphic is one role="img" with the figures spelled out in aria-label. A screen reader gets the numbers; it should never have to infer them from bar widths.

Radar

Six axes, three gridline rings, an accent polygon filled at 16%. More than six axes and the shape stops being readable; fewer than five and a bar chart says it better.

Ability radar

Gridlines use --chart-grid, which resolves to --hairline-soft. The fill opacity is 0.16 rather than the --accent-wash 12% — a wash sits over a flat surface, this sits over gridlines and needs a little more body.

Self-contained SVG cards

The pattern behind the profile README: an SVG that is a complete card — frame, type, data and animation in one file, with no external CSS. It has to stand alone because GitHub strips <style> from Markdown but honours it inside an SVG.

Card frame — the values that make it match
<svg xmlns="http://www.w3.org/2000/svg" width="100%" height="208"
     viewBox="0 0 880 208" fill="none" role="img"
     preserveAspectRatio="xMidYMid meet">

  <!-- The 0.5 offset is what keeps a 1px stroke crisp: a whole-pixel
       edge straddles two device pixels and renders as 2px of grey. -->
  <rect x="0.5" y="0.5" width="879" height="207" rx="20"
        fill="#ffffff" stroke="#000000" stroke-opacity="0.1"/>

  <!-- dark twin: fill="#1c1c1e" stroke="#ffffff" stroke-opacity="0.13" -->
</svg>

880 px wide for every card, so a column of them lines up. rx="20" is --r-lg. The stroke opacities are --hairline in each theme (10% and 13%).

SVG has no rem, so sizes are raw px and do not scale with the user's font setting. Keep card text at 9 px or above, and never put anything essential in it that is not also in the aria-label.

Animation — same curve and durations as the CSS
<style>
  /* 🔴 no-preference, not a `reduce` override. An SVG carries its own
     styles, so the global rule in base.css cannot reach inside it —
     the guard has to be repeated here or the card ignores the setting. */
  @media (prefers-reduced-motion: no-preference) {
    .fade { animation: fade 260ms cubic-bezier(.22, 1, .36, 1) both; }
    .rise { animation: rise 420ms cubic-bezier(.22, 1, .36, 1) both; }
    .grow { animation: grow 420ms cubic-bezier(.22, 1, .36, 1) both; }
    .draw { animation: draw 900ms cubic-bezier(.22, 1, .36, 1) both; }
    @keyframes fade { from { opacity: 0; transform: translateY(6px); } }
    @keyframes rise { from { opacity: 0; transform: translateY(12px); } }
    @keyframes grow { from { transform: scaleX(0); } }
    @keyframes draw { from { stroke-dashoffset: 1; } }
  }
</style>

<!-- Stagger in 0.04–0.05s steps. transform-origin must be explicit:
     an SVG element's default origin is the viewport corner, not itself. -->
<rect class="grow" style="transform-origin:0 80px;animation-delay:0.14s" …/>

260 ms is --dur, 420 ms is --dur-slow, and the curve is --ease. A card animating on a different curve from the page it sits on is the kind of mismatch nobody names but everybody feels.

Theming an SVG

Two routes, and which one you need depends on whether the SVG is inline or loaded as a file.

Inline in the page Use var(--token) and currentColor directly. The SVG is part of the document, so it inherits the theme with no extra work. This is the default for icons and diagrams.
Loaded as a file An <img src="…svg"> cannot see the page's custom properties. Ship a light/dark pair and switch with <picture>, as the profile README does.
The picture pattern
<picture>
  <source srcset="./assets/overview-dark.svg" media="(prefers-color-scheme: dark)">
  <img src="./assets/overview-light.svg" width="100%"
       alt="GitHub stats and most used languages: 42% TypeScript, 24% Go…">
</picture>

The alt has to carry the actual figures. A reader who cannot see the card gets nothing from "GitHub stats card", and that is most of the value of the graphic.

One inconsistency worth deciding on The generated cards use #03724d / #4dff9a as the accent; tokens.css and cv.tanghoong.com use #03744e / #4dff9b. A one-digit drift in each, invisible side by side but real. The chart ramp above is recorded as-generated so it stays faithful to what ships today — worth aligning the two in whichever direction you prefer.

SVG checklist

  • Decorative icon: aria-hidden="true", and the control carries the label
  • Meaningful graphic: role="img" plus an aria-label that states the actual figures
  • Icons use currentColor — never a hard-coded hex
  • Stroke width matches the rendered size, not the 24 px viewBox
  • A file-loaded SVG has a light and a dark twin behind <picture>
  • Any animation inside the SVG repeats its own prefers-reduced-motion guard
  • transform-origin is set explicitly on anything that scales or rotates
  • 1 px strokes sit on a .5 offset so they stay crisp
  • No more than six series; the tail is grouped as "Other"
  • Checked in both themes — a chart that only works on white is half done
